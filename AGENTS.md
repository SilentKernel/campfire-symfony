# once-campfire-symfony

Campfire implemented natively in **Symfony 7.4 LTS on PHP 8.4**, served by **FrankenPHP in worker
mode**. It is a drop-in replacement for the Rails app: same SQLite database and schema, same
Active Storage files, same bcrypt passwords, same signed/encrypted cookies (people stay signed in
across a switch in either direction), same Action Cable protocol, and the original
Turbo/Stimulus/Lexxy frontend, unchanged.

## Oracles (read these; never edit them)

- `reference/` — the Rails app, git submodule pinned at `254dd1d` (app code identical to `659f957`,
  the revision the Laravel and Django ports pin). **The Ruby is the specification.** When matching
  behavior, read the controller/model/view/helper and cite it in a comment where the behavior is
  non-obvious (`// reference/app/models/room.rb`). When it depends on Rails or gem internals, read
  the gem source inside the reference image, not docs or memory:
  `docker run --rm --entrypoint bash campfire-reference:app -c 'cat $(bundle show actionpack)/lib/...'`.
- `tests/vectors/` — golden vectors generated by the Rails app (copied from once-campfire-rust,
  MIT). Crypto, cookies, CSRF, signed ids, SGIDs, Turbo stream names, routes, user agents, storage
  digests, Ruby string/float behaviour. Tests must pass against them; never edit them.
- `.cache/once-campfire-rust` — the Rust port, the most complete verified port (parity harness,
  seeds, rich-text corpus in `reference-tools/richtext`). Read it to see how a behaviour was
  matched. `.cache/once-campfire-{laravel,django,go,elixir}` are other ports. **Do not copy the
  Laravel port's markup**: its DOM ids diverge from Rails (`messages_room_1` vs Rails'
  `messages_rooms_open_1`).
- The seed: `var/seed/default/{db/production.sqlite3,storage/,labels.json}` (copy of the parity
  seed built by the Rails app; `bin/fetch-seed` refreshes it). `labels.json` maps names to ids
  (`rooms.watercooler`, `emails.david`, `passwords.all`, …).

## Compatibility contract (never break)

- SQLite schema exactly as `db/schema.sql` (= Rails `db/schema.rb`, incl. the FTS5
  `message_search_index` with the porter tokenizer). No new tables or columns in the Rails
  database. Our own state (Messenger queue) lives in `storage/db/jobs.sqlite3`.
- Timestamps are UTC text with microseconds (`rails_datetime` type).
- Active Storage blob keys, `storage/files/xx/yy/key` layout, variant records and digests.
- Cookies: `session_token` (signed, permanent), `_campfire_session` (encrypted: `session_id`,
  `_csrf_token`, `return_to_after_authenticating`, `flash`), `last_room` (plain, permanent).
- Rails masked and per-form CSRF tokens; signed ids (avatar, transfer, blob); SGIDs (mentions);
  Turbo signed stream names.
- Action Cable `actioncable-v1-json` on `/cable`, channel names and payloads as in
  `reference/app/channels`.
- HTML: same markup as the ERB views (element structure, ids, classes, data attributes), because
  the unchanged Stimulus controllers depend on it. Ids use Rails' `dom_id` (subclass names:
  `rooms_open_1`; messages use `client_message_id`). Escape like ERB (`'` → `&#39;`).
- Status codes and redirects as Rails (302 by default; 303/422 where the controller says so).

Record every deliberate difference in README.md "Known differences".

## Architecture and ownership

| Path | Namespace | What |
|---|---|---|
| `src/Rails/` | `App\Rails` | Framework-free Rails contracts: KeyGenerator, MessageVerifier, MessageEncryptor, cookie codecs, CSRF tokens, signed ids, GlobalID/SGID, Turbo stream names, ActiveSupport JSON, bcrypt. Vector-tested. |
| `src/Database/` | `App\Database` | SQLite middleware (Rails PRAGMAs, BEGIN IMMEDIATE), `Transactions` (after-commit), `rails_datetime` type |
| `src/Entity/`, `src/Repository/` | `App\Entity`, `App\Repository` | Doctrine ORM mapping of every Rails table. `Room` is single-table inheritance on `type` (`Rooms::Open/Closed/Direct`). |
| `src/Domain/` | `App\Domain\…` | Model behaviour that touches several records (Rails model methods/callbacks): `Domain\Rooms`, `Domain\Messages`, `Domain\Users`, … |
| `src/Http/` | `App\Http` | Request pipeline: `Current`, `RailsSession`, `Flash`, `Csrf`, `Params`, filter listeners, error pages |
| `src/Security/` | `App\Security` | Symfony Security authenticators (session cookie, bot key), voters |
| `src/Controller/` | `App\Controller\…` | One class per Rails controller, same names/namespaces (`Rooms\OpensController`, `Accounts\UsersController`). Routes are attributes; **route names are the Rails route names** (`room_messages`, `user_sidebar`). |
| `templates/` | — | Twig ports of `app/views`, **same relative paths** (`messages/_message.html.twig`, `rooms/show.html.twig`, `layouts/application.html.twig`). |
| `src/Twig/` | `App\Twig` | Twig extensions porting `app/helpers`, function names = Rails helper names (`avatar_tag`, `local_datetime_tag`, `button_to`, …) |
| `src/View/` | `App\View` | Rendering services (`MessageRenderer` with fragment caching, turbo streams) |
| `src/RichText/` | `App\RichText` | Action Text: sanitize, render attachments (mentions, opengraph), plain text, autolink |
| `src/Storage/` | `App\Storage` | Active Storage: blobs, disk service, signed URLs, variants (libvips), previews (ffmpeg), analysis |
| `src/Cable/` | `App\Cable` | Action Cable server (Workerman), channels, `Broadcaster` (unix socket publisher) |
| `src/Job/` | `App\Job` | Messenger messages (implement `AsyncJob`) and handlers: push, webhooks, banned content |
| `src/Push/`, `src/Opengraph/` | | Web Push delivery; link unfurling (SSRF-safe HttpClient) |
| `src/Command/` | `App\Command` | `campfire:install`, `campfire:cable` (backups: ONCE hooks in `hooks/`) |
| `assets/` | — | The original frontend (copied from `reference/app/{javascript,assets}` and `vendor/javascript`), served by AssetMapper with Rails' importmap keys |

Processes (one container, `bin/start`): `frankenphp run` (Caddy + PHP worker threads, gzip,
static assets, `/cable` reverse-proxied), `bin/console campfire:cable` (Action Cable server on
127.0.0.1:`TARGET_PORT`), `bin/console messenger:consume async` (jobs).

## Core APIs every feature uses

- **Time**: inject `Symfony\Component\Clock\ClockInterface` (UTC; frozen by `CAMPFIRE_FROZEN_TIME`).
  Never call `new \DateTime()`/`time()` for app timestamps. Doctrine timestamps are set by a listener.
- **Writes**: `App\Database\Transactions::transaction(fn () => …)`; side effects that Rails runs in
  `after_*_commit` go in `$transactions->afterCommit(fn () => …)`. Bulk statements (`update_all`,
  `insert_all`, `delete_all`), FTS and hot aggregates use DBAL (`Doctrine\DBAL\Connection`).
- **Request state**: `App\Http\Current` (user, session, request, authenticatedBy, account). It is
  reset after every request. **No static or instance state may survive a request** (worker mode):
  services holding per-request data implement `Symfony\Contracts\Service\ResetInterface`.
- **Session/flash/CSRF**: `App\Http\RailsSession`, `App\Http\Flash`, `App\Http\Csrf`.
- **Controllers** extend `App\Controller\ApplicationController` (helpers: `head()`,
  `turboStream()`, `respondTo()`, `redirectTo()`, `params()`, `current`). Controller-level access
  rules use attributes from `App\Http\Attribute` (`#[AllowUnauthenticatedAccess]`,
  `#[RequireUnauthenticatedAccess]`, `#[AllowBotAccess]`), mirroring Rails' class macros.
- **Broadcasting**: `App\Cable\Broadcaster` (`broadcast($stream, $payload)`,
  `disconnectUser($userId, $reconnect)`); call it from `afterCommit`.
- **Jobs**: dispatch a message implementing `App\Job\AsyncJob` on the Messenger bus.

## Working rules

- PHP 8.4, `declare(strict_types=1)`, final classes, readonly/constructor promotion, attributes for
  routes and mapping. Format with `vendor/bin/php-cs-fixer fix`; `vendor/bin/phpstan` must pass.
- Comments only where behaviour is non-obvious; cite the Rails file you matched.
- Tests live in `tests/` mirroring `src/` (`tests/Unit/…`, `tests/Functional/…`,
  `tests/Integration/…`). Functional tests extend `App\Tests\Support\CampfireTestCase`, which gives
  each test a fresh copy of the seed. Run `bin/phpunit` locally (host PHP is fine for iteration);
  `bin/check` runs the full suite in the production image (PHP 8.4 ZTS), which is authoritative.
- Never edit `reference/`, `tests/vectors/` or `.cache/`. Never `git commit`/`push`.
- Never benchmark an incomplete response as if it were the application. Raw benchmark output goes
  under `bench/results/<date>/`.
